# Project Rules

- Node.js app (Express + EJS + MySQL). PM2 is run manually with `pm2 start pm2.config.cjs` (app name "itsupport", script index.js); there are no PM2 npm scripts.
- After every change: git add ., commit with a clear message, and git push to origin main.
- Never commit .env. Config lives in .env (PORT 5009, DB_* vars for MySQL, SESSION_SECRET); .env.example lists the keys.
- Users have an optional display_name. Wherever a user is shown, use COALESCE(NULLIF(x.display_name, ''), x.username) (keep the existing column alias); req.user.name / currentUser.name is the signed-in user's shown name. The username is only for signing in.
- Users live only in the database, never in .env or code. Add them with `npm run create-user -- <username> <password>` or the Users page.
- Parameterised queries only. Never build SQL from user input.
- Every page requires login; every POST form needs the CSRF field (`<%- csrfField %>`).
- Schema changes go in db/schema.sql and must be safe to re-run (CREATE TABLE IF NOT EXISTS). `npm run seed` must stay safe to run twice.
- Categories, services, clients and knowledge base articles are always listed A-Z. Only service steps (/services/:id/steps/order, flowchart redrawn from the JSON reply) and inventory custom fields (generic [data-sortable-list] in app.js) can be reordered, by drag and drop via SortableJS.
- One-time migration steps (data changes that must never repeat) go in ONE_TIME_STEPS in scripts/migrate.js, recorded in schema_migrations.
- Uploads: multer, stored in uploads/ (or UPLOAD_DIR), outside public/, git-ignored, max 500 MB per file. Served only to signed-in users via /files/:name; only images, mp4/webm and PDF are shown inline, everything else is a download. Multipart requests are parsed and CSRF-checked in src/middleware/multipart.js before any route; a route must set `req.keepUploads = true` after recording files or they are deleted. Deleting a record must also delete its files from disk.
- Activity log: every route that writes to the database must call `logActivity()` (src/lib/activity.js) with the user, entity type, action, client (id + name snapshot) and subject (ticket title / service name). entity_id is the record whose History panel shows the entry (steps and notes -> client service id, comments -> ticket id, tutorials -> service id). Report days use UK time via `londonDate()`. Times are stored in UTC (pool timezone Z, session time_zone +00:00): set timestamps only with MySQL NOW()/CURRENT_TIMESTAMP, never from JavaScript. Display with fmtDate (Europe/London). Report and /activity turn a UK date into a UTC range with rangeCondition() (src/lib/report.js); manual entries use activity_date. KB edits pass `changes` (fields touched). New columns on existing tables go in ADDED_COLUMNS in scripts/migrate.js.
- Daily Report (/report, src/lib/report.js) is built only from activity_log rows for the chosen UK dates, from what was typed, never with a prefix of ours. It contains ONLY Log work entries and General IT Support (KB) articles created/edited. No ticket activity (comments, status, priority, reminders), no client service activity (commenced, steps, notes, completed) and no sent-report entries: those stay in activity_log and the History panels. Log work uses the typed text with the client put in by withClient() (already named: unchanged; "support ... regarding": "to {client}" before "regarding"; otherwise " for {client}"; no client: unchanged). One bullet per entry, grouped by user, ending "Other IT related tasks." Defaults to the signed-in user; the View dropdown (me / all / a user id) is remembered in users.report_view (a display preference, not activity-logged). Users with nothing to report that day are omitted. Every line is trimmed, capitalised, "setup" at the start becomes "Set up", one full stop, no semicolons. Manual entries are entity_type 'manual' and only their author can edit or delete them.
- The old report_actions / report_issues tables, action_id / issue_id / report_detail columns and services.report_phrase are no longer used. They are left in the database (and in db/schema.sql / migrate) so existing installs keep working; do not build on them.
- Tickets have a priority (low, normal default, high, urgent; src/lib/tickets.js) shown with views/partials/priority.ejs as LED flags (Low #39FF14, Normal #00E5FF, High #FFB000, Urgent #FF1744, dark text) that share one 1.5s led-pulse animation; no pulse with prefers-reduced-motion. Every ticket change (edit, status, priority, comment) sets updated_by and updated_at. Priority changes go in ticket_history (old_priority/new_priority) and activity_log. Ticket lists (Tickets page and client page) use src/lib/ticket-list.js and views/partials/ticket-table.ejs: columns priority flag | # | Title | Client | Status (pill) | Created by | Updated by (avatar + firstName(), full name in the tooltip) | Last updated (fmtShort, "7 Oct, 19:11", right-aligned) | delete icon (shown on row hover), coloured left border kept; status + priority pills and the search box on one row (ticket-filters.ejs with search); sortable headers (whitelisted SQL; the flag header sorts by priority), default order urgent first then last updated.
- Tasks were replaced by ticket reminders. The tasks table (and notifications.task_id) stay in the database so existing installs keep working; nothing reads or writes them, do not build on them.
- Ticket reminders (src/routes/reminders.js, src/lib/reminders.js, views/partials/reminders-panel.ejs and reminder-fields.ejs): Reminders panel on the ticket page (pending soonest first, done list), add / edit / done / delete; note, for (one or more users, default me: chips with x plus an "Add people" dropdown ([data-user-multi] in app.js: search, stays open while ticking, Done / Esc / click outside close it keeping the choice, at least one required; the checkboxes are what is submitted); reminder_recipients (reminder_id, user_id, snoozed_until, sent_at, done_at) is the source of truth, reminders.for_user_id only mirrors the first and reminders.snoozed_until / email_sent_at are no longer used), UK date+time with quick picks (In 1 hour, 15:00 today, tomorrow 09:00, next Monday 09:00, Custom) computed in Europe/London in app.js. remind_at is converted with londonLocalToUtc()/toLondonInput() (src/lib/activity.js), the only times set from JavaScript besides reminder_recipients.snoozed_until. Due for a recipient = COALESCE(rr.snoozed_until, remind_at) <= NOW(), their done_at NULL and status 'pending'; editing the time clears everyone's snooze and sent_at. Each recipient marks Done or snoozes for themselves (setRecipients / markDone / snoozeFor); the panel shows who is done ("X of N done"); the reminder becomes status 'done' when every recipient is done, or when the creator uses "Done for everyone". Every change logs entity_type 'reminder', entity_id = ticket id (ticket History), and is never on the Daily Report. The add and edit forms end with Save and Cancel; a save redirects with flash type 'saved', shown as a "Saved" toast (foot.ejs, data-autohide) instead of the banner. Ticket lists show a bell (tooltip: next reminder time) on rows with a pending reminder.
- Notifications (GET /notifications/poll, src/routes/notifications.js, bellFor() in src/lib/reminders.js): the browser polls every 60s; each poll gives each of the user's due reminders (per recipient) one unread notifications row (type 'ticket_reminder', reminder_id, channel 'portal'; 'email'/'teams' reserved for later). Done, snooze (10m / 1h / tomorrow 09:00 UK), edit and delete mark it read, so a reminder notifies again when next due. Due and missed reminders are toasts that stay until Done or Snooze (soft WebAudio chime once, when delivered_at is first set); the bell shows the count and Mentions (unread, opened via GET /notifications/:id/open which marks read) / Due now / Missed (before today, UK) / Upcoming (7 days).
- @mentions (src/lib/mentions.js): typing @ in the ticket comment box opens a user list (template[data-mention-users] + [data-mention-box] in app.js: filter, arrows + Enter/Tab, Esc) and inserts "@Display Name", highlighted by a backdrop layer. On save findMentioned() matches "@Name" of portal users (longest first, start or after a space/bracket/quote, so emails are not mentions) into comment_mentions (comment_id, user_id); each mentioned user except the author gets a notifications row (type 'mention', link /tickets/:id#comment-:cid) and, after commit, an email via sendMail (kind 'mention', From MAIL_FROM, subject "{Author} mentioned you on #{id} {title}", client, title, comment, Open ticket button). Logged as ticket_comment / sent (History only, never the Daily Report). Comments render with mentionHtml() (escaped, <span class="mention">). Viewing the ticket marks its mention notifications read.
- Email (src/lib/mailer.js, nodemailer): the only way to send mail. SMTP_HOST, SMTP_PORT (587 STARTTLS), SMTP_USER, SMTP_PASS, MAIL_FROM_EMAIL, MAIL_FROM_NAME (+ APP_URL for links) from .env; when any is missing, mailStatus() is disabled and sendMail() returns { ok: false, error } with a clear message (never throws). Every attempt is logged in email_log. A user's email address is their username when it is an email (userEmail()); there is no separate email column.
- Reminder emails: a 60s timer in index.js calls sendDueReminderEmails() (src/lib/reminders.js), which claims reminder_recipients.sent_at per recipient before sending, so each recipient's due time is emailed once; their snooze and time edits clear it. Only reminders due in the last 24 hours are emailed. Branded HTML, subject "Reminder: {note}".
- Send report (POST /report/send, src/lib/report-email.js): each user emails only their own report. The browser posts the edited preview as JSON text; the server rebuilds the HTML (escaped, Calibri 11pt, bold heading, real bullets) and appends the sanitised signature, so no browser HTML is sent. From the user when their address ends @cleartwo.co.uk, otherwise from MAIL_FROM_EMAIL with Reply-To the user; report emails carry the header X-MC-PreserveRecipients: true (Mandrill sends one email showing all To and CC); the sender is not copied automatically: the "Send me a copy" checkbox (users.report_copy, remembered) adds them as BCC. Subject "EOD {d Month}" (UK date). Last recipients are saved in users.report_to / report_cc; suggestions are earlier recipients (email_log) and portal users. Each send logs entity_type 'report', action 'sent', activity_date = report date (shown as "Sent to … at HH:MM"; never on the report).
- My profile (/profile, src/routes/profile.js; shared logic in src/lib/profile.js, also used by the Users page so admins can edit anyone): picture, display name, job title, reminder notifications, date format, signature, password, active sessions. Every change logs entity_type 'user' (never on the Daily Report).
- Profile pictures (src/lib/avatars.js): choosing a file opens the shared Crop picture popup (views/partials/crop-dialog.ejs, in foot.ejs; plain canvas in app.js, no library): drag, slider / wheel / pinch zoom, rotate 90°, reset, live circle previews; Save uploads only a 512x512 JPG (quality 0.9) with fetch (redirect: manual, then back to data-back so the flash survives). Without JS the original is posted. The server checks it (JPG/PNG/WebP, max 5 MB), takes the centre square, resizes to 256px WebP with sharp, stored in UPLOAD_DIR/avatars with a random name in users.avatar_file, served only to signed-in users via /avatars/:name. Replacing, removing or deleting the user deletes the file. Show users with the avatar({ id, name }, 'xs'|'sm'|'md'|'lg') view helper (loaded per page in index.js; falls back to a coloured circle with initials, and looks a bare name up when there is no id). Use it wherever a user is shown.
- Job title (users.job_title): optional; shown on My profile and the Users list; {job_title} in a signature is replaced (escaped) by fillSignature() when the report is sent and in previews.
- Reminder notifications (users.reminder_channel popup/email/both, default both): bellFor() only creates notifications, toasts and the sound for popup/both; sendDueReminderEmails() only emails email/both.
- Date format (users.date_format d_mon_yyyy "7 Oct 2026" / dd_mm_yyyy "07/10/2026", src/lib/dates.js): requireAuth puts the user's fmtDate (date + 24h UK time), fmtDay (DATE columns or a timestamp's UK day) and fmtTime in res.locals and req.fmt. Never print a raw date or call toLocale* in views; routes use req.fmt. Email subjects keep "EOD 7 October"; Daily Report day headings keep the long "Wednesday 7 October 2026".
- Active sessions (src/lib/sessions.js, user_sessions table): the session store is set with setStore(); sign-in and every request (at most once a minute) record user, user agent, IP and last_active; logout forgets the row. Signing a session out destroys it in the store and deletes the row. Changing (My profile) or resetting (Users) a password calls signOutOtherSessions().
- Email signatures (users.email_signature, MEDIUMTEXT): edited in the rich text / Paste HTML editor (views/partials/signature-editor.ejs, app.js) on the Users edit popup, the Add user form and My profile (/profile, src/routes/profile.js: own display name, signature, password with the current password). Always sanitise with src/lib/signature.js (sanitize-html) before saving and before sending; previews render in a shadow root after a browser-side clean-up. CSP img-src allows https: for linked signature images.
- Inventory (/inventory, src/routes/inventory/{index,records,fields,stock,settings}.js, src/lib/inventory/*.js, views/inventory/) is internal (our own staff, accounts and kit, never clients). Rebuilt Oct 2026; the old inv_* / custom_field* tables were dropped by the one-time migrate step inventory_v2_reset (an explicit exception to "never drop"; do not drop anything else). Tables: inventory_tabs (kind employees / ex_employees / stock / records), inventory_fields (per tab_id or stock category_id; types in FIELD_TYPES; role title / user_id / email), inventory_records (status active / inactive + leaving_date for employees), inventory_values, stock_categories (group_by none / platform / field for the breakdown), stock_items (one per physical item), stock_values, stock_assignments (snapshots; "Equipment held"), inventory_widths (per-user column widths). Defaults are installed once by inventory_v2_defaults (src/lib/inventory/defaults.js). Password and PIN fields are stored ONLY encrypted (AES-256-GCM, ENCRYPTION_KEY, src/lib/inventory/secrets.js) in inventory_values.value_enc: never store, log, export or render plain text; lists only know whether one is set; POST /inventory/secret reveals or copies one and logs it (entity_type inv_secret, actions viewed / copied). Without a valid key, refuse to save them with keyStatus().message. Tables use views/inventory/_grid.ejs (+ "Inventory grids" in app.js): search, sort, filter row, CSV of the shown rows (secrets as "(hidden)"), drag headers to reorder (saved for everyone via .../columns/order), drag edges to resize (POST /inventory/widths, per user). Deactivating an employee needs a leaving date, returns every item to stock (returnAll) and keeps fields; ex employees are read-only until reactivated. Every inventory write logs inv_record / inv_item (personId = employee for their History) / inv_config; inventory is never on the Daily Report. Stock categories and tabs are ordered by drag (sort_order). Record pages (employee profile, Writers / Old Accounts / custom tabs) manage the tab's fields in place: "+ Add field" / "+ Add access" (views/inventory/_add-field.ejs -> POST /t/:id/columns), a hover "⋯" menu per field (_field-menu.ejs: /fields/:id/rename, /type, /move, /hide, delete page) and drag within Details or Access (POST /t/:id/columns/group-order, only that group moves); every change posts back=<page> to return there, goes through the same validation as the Columns page and is logged as inv_config. Changes apply to the whole tab and its table columns. Templates and import (src/routes/inventory/imports.js, mounted before /stock; src/lib/inventory/template.js, import-files.js, import-plan.js; views/inventory/import/): templates list the current visible fields (+ Status / Leaving date for Employees; Stock core columns + category fields) with an Instructions sheet and Lists-sheet dropdowns. Upload .xlsx/.csv (20 MB, 5000 rows) -> the file is deleted right after parsing and the rows are staged ONLY as an AES-GCM encrypted file in UPLOAD_DIR/imports (per user, 1 hour, deleted on confirm / cancel), so imports need ENCRYPTION_KEY. Map (auto-match by normalised header; skip / map / create field) -> Preview (planRecords / planStock: create, update, no change, skip with reasons; secrets masked; rows with errors are skipped, never guessed) -> Confirm re-plans inside one transaction and applies. Matching: Employees by User-ID then Email, Writers by Official-ID, Old Accounts by Gmail-ID, other tabs by the name field, Stock by serial. Employee User-IDs follow the MDP rules (IDs typed or reclaimed by reactivated rows are reserved first). Stock "Assigned to" (User-ID or name): active -> assigned; ex employee -> stays Available and gets a stock_assignments row (Equipment held). Empty cells NEVER change saved data (access and secrets included); the text CLEAR clears a value; a password equal to the saved one (decrypted in memory) is "no change". Example rows marked "EXAMPLE (delete this row)" (EXAMPLE_MARK) are never imported. Full workbook (src/lib/inventory/workbook.js, src/routes/inventory/workbook.js, views/inventory/workbook/, "Workbook" in the tab bar): export = ONE .xlsx (never CSV or zip) with a sheet per tab in tab order (Employees = active, Stock, Writers, Ex Employees = inactive employees with the Employees columns, Old Accounts, custom tabs) with ALL fields and data, then Instructions, Lists; import accepts only that .xlsx; the main Inventory page has no CSV export (CSV stays in each tab's grid); passwords blank unless "Include passwords" (decrypted, logged as inv_config / exported). Import = every sheet matched to a tab by name (Ex Employees -> Employees as inactive; unknown sheets: skip or create a new tab whose first column is its name), mapped per sheet, previewed and confirmed in one transaction in order Employees, Stock, other tabs, new tabs (planAll; Stock previews can match employees added by the same workbook). The import is logged as inv_config / uploaded with counts (plus per-record entries); never row values. The error report CSV masks secrets as (hidden). Never pass a view local named scope (EJS treats it as an option): inventory views use area. Employee User-IDs (field role user_id; src/lib/inventory/userids.js): PREFIX-001 (3+ digits; prefix in inventory_settings user_id_prefix, default MDP, edited in Settings); new employees get the lowest number not used by an ACTIVE employee (suggested on the Add form, can be changed to any free one; "21" / "mdp21" normalise to MDP-021); uniqueness is only among active employees, ex employees keep theirs; create / edit / reactivate call lockEmployees() and resolveId() inside the transaction; reactivation keeps the old ID if free, else gives the lowest free one and logs "User-ID changed from X to Y on reactivation". Records are always identified by their internal id (shown as Record #id), never by User-ID; log lines name employees as "Name (MDP-013)".
- Knowledge base (/kb) issue and solution are Markdown, rendered with marked and sanitised with sanitize-html (src/lib/markdown.js). Never output user HTML unsanitised.
- Client pickers use the searchable dropdown component (data-combobox on a <select> or an <input list=...>, enhanceCombobox() in public/js/app.js): type to filter, arrows + Enter, Esc / click outside, clear button. The original field stays in the form and is what gets submitted. Use it for every client field (and any other long list).
- Inline edit popovers (`<details class="edit">`) have Save and Cancel (`data-cancel`); Esc or a click outside closes them and discards changes (public/js/app.js).
- No frontend framework: EJS views, plain responsive CSS in public/css/style.css, Mermaid and SortableJS from cdn.jsdelivr.net.
- Compact UI: html font-size 14px (rem sizes follow), 13px (--fs-table) for table cells, labels and buttons; spacing tokens --sp-1..5 (4/8/12/16/24px); radius 8px cards, 6px inputs, round pills; buttons and inputs --control-h 34px, filter pills --pill-h 28px; page max width --page-max 1440px, centred. Sidebar --sidebar-w 220px, collapsible to icons (cookie itsupport_nav, read server-side as navCollapsed so it never flashes). List tables (.table) are table-layout: fixed with widths on the header cells (w-xs/w-id/w-num/w-sm/w-md/w-15/w-20/w-25; others share the rest), one line per cell with ellipsis (app.js adds the full text as a tooltip), 44px rows, sticky header, hover highlight; they never scroll sideways on a laptop, only below 900px inside .table-wrap.
- Branding: deep indigo #200D6C (sidebar, headings, top bar), blue #0390D7 (primary buttons, links, active nav, focus), purple #6741C3 (accents, hover, badges, flowchart nodes), black #000000 text, white cards on #F5F5F7 with #E5E5EA borders. Status badges: Open #0390D7, Customer Waiting #6741C3, Closed grey. Colours are CSS variables at the top of public/css/style.css. Kollektif (body) and Made Tommy (headings) from public/fonts, falling back to Poppins, then sans-serif.
- npm scripts: start (node index.js, foreground for testing, Ctrl+C stops it), migrate, seed, create-user.
- Logo is public/logo.png (/logo.png); favicon is public/favicon.svg (/favicon.svg).
- Do not test locally: no starting the app and no connecting to the database. `npm install` and `node --check` on .js files are fine.
- Keep README server setup steps up to date.
