# Project Rules

- Node.js app (Express + EJS + MySQL). PM2 is run manually with `pm2 start pm2.config.cjs` (app name "itsupport", script index.js); there are no PM2 npm scripts.
- After every change: git add ., commit with a clear message, and git push to origin main.
- Never commit .env. Config lives in .env (PORT 5009, DB_* vars for MySQL, SESSION_SECRET); .env.example lists the keys.
- Users have an optional display_name. Wherever a user is shown, use COALESCE(NULLIF(x.display_name, ''), x.username) (keep the existing column alias); req.user.name / currentUser.name is the signed-in user's shown name. The username is only for signing in.
- Users live only in the database, never in .env or code. Add them with `npm run create-user -- <username> <password>` or the Users page.
- Parameterised queries only. Never build SQL from user input.
- Every page requires login; every POST form needs the CSRF field (`<%- csrfField %>`).
- Schema changes go in db/schema.sql and must be safe to re-run (CREATE TABLE IF NOT EXISTS). `npm run seed` must stay safe to run twice.
- Categories, services, clients and Articles are always listed A-Z. Only service steps (/services/:id/steps/order, journey redrawn from the JSON reply journeyHtml) and inventory custom fields (generic [data-sortable-list] in app.js) can be reordered, by drag and drop via SortableJS.
- One-time migration steps (data changes that must never repeat) go in ONE_TIME_STEPS in scripts/migrate.js, recorded in schema_migrations.
- Uploads: multer, stored in uploads/ (or UPLOAD_DIR), outside public/, git-ignored, max 500 MB per file. Served only to signed-in users via /files/:name; only images, mp4/webm and PDF are shown inline, everything else is a download. Multipart requests are parsed and CSRF-checked in src/middleware/multipart.js before any route; a route must set `req.keepUploads = true` after recording files or they are deleted. Deleting a record must also delete its files from disk. Ticket attachments (src/lib/ticket-files.js, ticket_attachments, comment_id NULL = on the ticket): max 100 MB each (checked in the route), moved to UPLOAD_DIR/tickets after the rows are saved (keepTicketFiles), served by /files/:name like the others; deleting an attachment, comment, ticket or client removes the files (attachmentNames + removeTicketFiles).
- Activity log: every route that writes to the database must call `logActivity()` (src/lib/activity.js) with the user, entity type, action, client (id + name snapshot) and subject (ticket title / service name). entity_id is the record whose History panel shows the entry (steps and notes -> client service id, comments -> ticket id, tutorials -> service id). Report days use UK time via `londonDate()`. Times are stored in UTC (pool timezone Z, session time_zone +00:00): set timestamps only with MySQL NOW()/CURRENT_TIMESTAMP, never from JavaScript. Display with fmtDate (Europe/London). Report and /activity turn a UK date into a UTC range with rangeCondition() (src/lib/report.js); manual entries use activity_date. KB edits pass `changes` (fields touched). New columns on existing tables go in ADDED_COLUMNS in scripts/migrate.js.
- Daily Report (/report, src/lib/report.js) is built only from activity_log rows for the chosen UK dates, from what was typed, never with a prefix of ours. It contains ONLY Log work entries and Articles (kb_article, formerly General IT Support / KB) created/edited, worded "Documented a solution for '{title}' in Articles." / "Updated the article '{title}'.". No ticket activity (comments, status, priority, reminders), no client service activity (commenced, steps, notes, completed) and no sent-report entries: those stay in activity_log and the History panels. Log work uses the typed text with the client put in by withClient() (already named: unchanged; "support ... regarding": "to {client}" before "regarding"; otherwise " for {client}"; no client: unchanged). One bullet per entry, grouped by user, ending "Other IT related tasks." Defaults to the signed-in user; the View dropdown (me / all / a user id) is remembered in users.report_view (a display preference, not activity-logged). Users with nothing to report that day are omitted. Every line is trimmed, capitalised, "setup" at the start becomes "Set up", one full stop, no semicolons. Manual entries are entity_type 'manual' and only their author can edit or delete them.
- The old report_actions / report_issues tables, action_id / issue_id / report_detail columns and services.report_phrase are no longer used. They are left in the database (and in db/schema.sql / migrate) so existing installs keep working; do not build on them.
- Tickets have a priority (low, normal default, high, urgent; src/lib/tickets.js) shown with views/partials/priority.ejs as LED dots (span.led led-{p}; Low #39FF14, Normal #00E5FF, High #FFB000, Urgent #FF1744) that share one 1.6s led-pulse animation; no pulse with prefers-reduced-motion. Every ticket change (edit, status, priority, comment) sets updated_by and updated_at. Priority changes go in ticket_history (old_priority/new_priority) and activity_log. Ticket lists (Tickets page and client page) use src/lib/ticket-list.js and views/partials/ticket-table.ejs (the title cell also shows the reminder bell and a paperclip with attachment_count): columns priority flag | # | Title | Client | Status (pill) | Created by | Updated by (avatar + firstName(), full name in the tooltip) | Last updated (fmtShort, "7 Oct, 19:11", right-aligned) | delete icon (shown on row hover), coloured left border kept; status + priority pills and the search box on one row (ticket-filters.ejs with search); sortable headers (whitelisted SQL; the flag header sorts by priority), default order urgent first then last updated.
- Tasks were replaced by ticket reminders. The tasks table (and notifications.task_id) stay in the database so existing installs keep working; nothing reads or writes them, do not build on them.
- Ticket reminders (src/routes/reminders.js, src/lib/reminders.js, views/partials/reminders-panel.ejs, reminder-fields.ejs and reminder-people.ejs): Reminders panel on the ticket page (pending soonest first, done list), add / edit / done / delete; note, for (one or more users, default me: chips with x plus an "Add people" dropdown ([data-user-multi] in app.js: search, stays open while ticking, Done / Esc / click outside close it keeping the choice, at least one required; the checkboxes are what is submitted); reminder_recipients (reminder_id, user_id, snoozed_until, sent_at, done_at) is the source of truth, reminders.for_user_id only mirrors the first and reminders.snoozed_until / email_sent_at are no longer used), UK date+time as two text fields, remind_date dd/mm/yyyy and remind_time HH:MM 24h (readWhen(); no native datetime box), with a portal-styled calendar and 30-minute time list, quick picks (In 1 hour, 15:00 today, tomorrow 09:00, next Monday 09:00, Custom) computed in Europe/London in app.js ([data-reminder-when]) and inline validation (the form is noValidate, never browser popups). New reminders default to tomorrow 09:00 (reminders.defaultInput, that pick shown as chosen); Edit is pre-filled and only writes what changed. Each row (pending and done) has an "Add people" popover posting only the people picker to POST /reminders/:id/recipients. New people on a reminder still to come get it at the due time; on one already due or done they are emailed straight away ("{User} added you to a reminder: {note}", claimAddedEmails() claims their sent_at, emailAddedRecipients() after commit, only for email/both) and a done reminder becomes pending again; people already on it are never re-emailed. remind_at is converted with londonLocalToUtc()/toLondonInput() (src/lib/activity.js), the only times set from JavaScript besides reminder_recipients.snoozed_until. Due for a recipient = COALESCE(rr.snoozed_until, remind_at) <= NOW(), their done_at NULL and status 'pending'; editing the time clears everyone's snooze and sent_at. Each recipient marks Done or snoozes for themselves (setRecipients / markDone / snoozeFor); the panel shows who is done ("X of N done"); the reminder becomes status 'done' when every recipient is done, or when the creator uses "Done for everyone". Every change logs entity_type 'reminder', entity_id = ticket id (ticket History), and is never on the Daily Report. The add and edit forms end with Save and Cancel; a save redirects with flash type 'saved', shown as a "Saved" toast (foot.ejs, data-autohide) instead of the banner. Ticket lists show a bell (tooltip: next reminder time) on rows with a pending reminder.
- Notifications (GET /notifications/poll, src/routes/notifications.js, bellFor() in src/lib/reminders.js): the browser polls every 60s; each poll gives each of the user's due reminders (per recipient) one unread notifications row (type 'ticket_reminder', reminder_id, channel 'portal'; 'email'/'teams' reserved for later). Done, snooze (10m / 1h / tomorrow 09:00 UK), edit and delete mark it read, so a reminder notifies again when next due. Due and missed reminders are toasts that stay until Done or Snooze (soft WebAudio chime once, when delivered_at is first set); the bell shows the count and Mentions (unread, opened via GET /notifications/:id/open which marks read) / Due now / Missed (before today, UK) / Upcoming (7 days).
- @mentions (src/lib/mentions.js) and comment emails (src/lib/comment-emails.js): typing @ in a ticket comment box (the composer and the edit-comment popup) opens a user list (template[data-mention-users] li[data-id][data-name] + [data-mention-box] in app.js: filter, arrows + Enter/Tab, Esc) and inserts "@Display Name", highlighted by a backdrop layer; each pick adds the user id to the form's hidden mention_ids. On save recordMentions(..., picked) mentions ONLY users whose id was picked (or who were already mentioned in that comment) and whose "@Name" is still in the text (findMentioned: longest first, start or after a space/bracket/quote, so an "@" inside an email address is never a mention) into comment_mentions (comment_id, user_id); newly mentioned users except the author get a notifications row (type 'mention', link /tickets/:id#comment-:cid) only when their notify_channels include popup, and a desktop push (pushMentionsTo) only with desktop. After commit sendCommentEmails() sends one email per recipient via sendMail (email_log; skipped ones logged with logSkipped): a new comment goes to every admin (users.role 'admin'; all portal users are admins) except the author, subject "New comment on #{id} {title} ({client})" (kind 'comment': author, UK time, the comment, attachments listed, status, priority, Open ticket button), and the newly mentioned get ONE email instead, subject "{Author} mentioned you on #{id} {title}" (kind 'mention', their mention highlighted at the top); an edited comment emails only the newly mentioned. Emails always go regardless of notify_channels. Logged as ticket_comment / sent (History only, never the Daily Report). Comments render with mentionHtml() (escaped, <span class="mention">). Viewing the ticket marks its mention notifications read.
- Email (src/lib/mailer.js, nodemailer): the only way to send mail. SMTP_HOST, SMTP_PORT (587 STARTTLS), SMTP_USER, SMTP_PASS, MAIL_FROM_EMAIL, MAIL_FROM_NAME (+ APP_URL for links) from .env; when any is missing, mailStatus() is disabled and sendMail() returns { ok: false, error } with a clear message (never throws). Every attempt is logged in email_log. A user's email address is their username when it is an email (userEmail()); there is no separate email column.
- Reminder emails: a 60s timer in index.js calls sendDueReminderEmails() (src/lib/reminders.js), which claims reminder_recipients.sent_at per recipient before sending, so each recipient's due time is emailed once; their snooze and time edits clear it. Only reminders due in the last 24 hours are emailed. Branded HTML, subject "Reminder: {note}".
- Send report (POST /report/send, src/lib/report-email.js): each user emails only their own report. The browser posts the edited preview as JSON text; the server rebuilds the HTML (escaped, Calibri 11pt, bold heading, real bullets) and appends the sanitised signature, so no browser HTML is sent. From the user when their address ends @cleartwo.co.uk, otherwise from MAIL_FROM_EMAIL with Reply-To the user; report emails carry the header X-MC-PreserveRecipients: true (Mandrill sends one email showing all To and CC); the sender is not copied automatically: the "Send me a copy" checkbox (users.report_copy, remembered) adds them as BCC. Subject "EOD {d Month}" (UK date). Last recipients are saved in users.report_to / report_cc; suggestions are earlier recipients (email_log) and portal users. Each send logs entity_type 'report', action 'sent', activity_date = report date (shown as "Sent to … at HH:MM"; never on the report).
